# GroceryStore Frontend Engineering Guidelines & Vibe-Coding Standards

Этот файл является обязательным руководством для Gemini CLI при разработке клиентской части проекта GroceryStore (GroceryStore-front).

---

## 1. Стек технологий и архитектура

- **Фреймворк**: Next.js 15 (App Router), React 19, TypeScript (strict).
- **Стилизация**: Tailwind CSS, Radix UI primitives, Lucide Icons.
- **Анимации**: Framer Motion (framer-motion).
- **Стейт и запросы**: TanStack Query / SWR / Server Actions.
- **Архитектура папок**: Feature-Sliced Design (FSD) или модульная структура (app/, widgets/, features/, entities/, shared/).

---

## 2. Стандарты UI/UX (High-End Aesthetic)

### 2.1. Визуальный дизайн
- **Сетка и геометрия**: Модульная сетка с кратностью 4px/8px, скругления rounded-2xl / rounded-3xl для карточек и модалок.
- **Границы и глубина**: Тонкие аккуратные бордеры border-neutral-200 dark:border-neutral-800, мягкие тени shadow-sm, эффект стекла backdrop-blur-md bg-background/80.
- **Микроинтеракции**: Плавные переходы для всех кнопок и ссылок (transition-all duration-200 active:scale-[0.98]).
- **Бренд-палитра**: Акцентный свежий изумрудный цвет (Emerald/Green).

### 2.2. Обязательные 4 состояния каждого компонента
1. **Loading State**: Мерцающие скелетоны (Skeleton / shimmer effects), в точности повторяющие геометрию загружаемого контента. Запрещено использовать голые спиннеры на всю страницу.
2. **Empty State**: Если список пуст (товары, заказы, избранное, результаты поиска) — показывать дружелюбный блок с иконкой, пояснением и кнопкой действия (CTA).
3. **Error State**: Понятное сообщение об ошибке с кнопкой «Повторить попытку» (Retry), всплывающие тосты (Sonner / Hot-Toast).
4. **Disabled / Pending State**: Блокировка кнопок во время сетевого запроса со спиннером и сменой текста («Сохранение...»), защита от дублирующих кликов.

## 3. Протокол вайбкодинга и непрерывного тестирования (Zero-Interruption Workflow)

Пользователь часто тестирует приложение параллельно с работой агента на http://localhost:3000. При этом работает Next.js Fast Refresh (HMR).

**Агент ОБЯЗАН соблюдать следующие правила:**

1. **Не ломать пользовательский экран во время набора кода:**
   - Никаких промежуточных поломок кода в основной рабочей копии пользователя.
   - Для масштабных задач, рефакторинга компонентов или добавления новых страниц агент работает через **изолированное Git Worktree**:
     git worktree add ../GroceryStore-front-ai -b feat/task-name
   - Внутри изолированного каталога агент пишет код, устанавливает зависимости и запускает проверки.
2. **Обязательный Pre-Merge Quality Gate:**
   - Перед слиянием изменений в рабочую ветку пользователя (dev) агент обязан запустить:
     yarn typecheck && yarn lint
   - Код переносится в основную ветку пользователя **только когда все типы и проверки на 100% зеленые**.
   - Перенос происходит атомарно (Fast-Forward Merge), благодаря чему Fast Refresh в браузере пользователя обновляет страницу мгновенно и без красных экранов.
   - После завершения временное воркдерево удаляется:
     git worktree remove ../GroceryStore-front-ai
3. **Регламент удаленного сервера (94.156.154.243):**
   - Никаких спонтанных пересборок и деплоев на сервер в процессе локальной разработки.
   - Деплой на боевой сервер производится **только по прямой просьбе пользователя** («задеплой на сервер», «обнови прод»).

## 4. Команды проверки качества

- yarn typecheck — Проверка типов TypeScript (без сборки)
- yarn lint — Проверка линтера
- yarn build — Сборка проекта
